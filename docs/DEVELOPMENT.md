# Heart Rate Strap Companion — V0.0.1 开发规格

> 本文档是 V0.0.1 的最高优先级产品与工程约束。若实现细节与本文冲突，以本文为准。

## 1. 版本目标

V0.0.1 只实现“持续记录”，暂不实现“骑行记录”。骑行入口保留但标记为即将推出。

核心闭环：

1. 首次启动给出后台保活说明，明确提示用户在系统最近任务/手机管家中对本应用执行“加锁/允许后台运行”。Android 没有统一的“应用加锁”授权 API，因此应用只做厂商适配跳转和清晰指导，不伪造授权状态。
2. 扫描并连接标准 BLE Heart Rate Service（0x180D）心率带，读取 Heart Rate Measurement（0x2A37）。
3. 主界面每秒刷新一次当前心率；设备卡可点击切换设备。
4. 点击“持续记录”进入记录页；记录期间每秒落库一条有效心率样本。
5. 记录页显示实时心率和可左右拖动的心率曲线。默认窗口为最新 1 小时；X 轴使用真实 24 小时时间 `HH:mm`；拖动到记录首尾时允许有限超拖并回弹。
6. 应用进入后台且正在记录时显示可拖动悬浮窗；单击悬浮窗回到当前持续记录页。
7. 停止记录采用长按确认，防止误触。记录落库后进入历史列表可复查。
8. 历史记录按开始时间倒序（最新在最上）显示：记录类型、`yyyy-MM-dd HH:mm`、总时长、最大心率、平均心率。点击记录后以放大卡片/弹层展示详情，背景在 Android 12+ 使用真实模糊，旧版本采用半透明降级；详情曲线与实时曲线共用同一组件和手势逻辑。

## 2. 技术栈与兼容范围

- Android 原生应用，业务代码使用 Java。
- Gradle 多模块：`:core`（纯 Java、平台无关算法/数据协议）与 `:app`（Android 平台实现）。
- `minSdk 26`，`targetSdk 35`，Java 17 toolchain。
- AndroidX + Material Components + Room。
- BLE 使用 Android 原生 GATT API，不绑定迈金 H303 私有协议；只要设备正确实现标准 BLE 心率服务即可工作。
- 持续连接与记录运行在前台服务中，Android 14+ 声明 `connectedDevice` 前台服务类型。

### 2.1 跨移动端准备

Java/Android UI 本身不能直接运行在 iOS。V0.0.1 不假装“一套 Java 代码全平台”。跨平台准备采用边界隔离：

- BLE 数据包解析、心率坐标档位计算、记录统计模型放在纯 Java `core` 模块，不依赖 `android.*`。
- Android BLE、Room、悬浮窗、权限、通知全部放在 `app` 平台适配层。
- 数据模型使用稳定字段：`timestampMs`、`bpm`、`recordingType`、`startTimeMs`、`endTimeMs`、`maxBpm`、`avgBpm`。
- 后续 iOS/跨平台版本可按同一接口和数据契约重写平台层，图表交互规范与数据库语义保持一致。

## 3. UI 视觉规范

整体采用深色科技感但避免“游戏化”：深墨黑/深青背景、低对比网格、绿色作为实时数据主强调色。圆角、留白、阴影统一，不使用大面积荧光色。

### 3.1 数字稳定布局（强制）

- 所有 0–999 的心率主数字必须使用三个独立数字 TextView 固定槽位渲染（百/十/个位），禁止把 `123` 作为一个普通 TextView 直接显示。
- 个位数与两位数使用前导空槽而不是改变整体宽度，例如 `  8`、` 72`、`123`，从而保证每个数字位置不跳动。
- 最大/平均心率的小型读数同样优先使用三槽组件。
- 日期、时间、时长超过 3 位，不能强行塞进三个槽；这些字段使用逐字符等宽/固定宽度渲染策略，保证数字变化时不引发布局抖动。分隔符（`-`、`:`）不参与数字槽宽度变化。

## 4. 主界面

顶部：

- 页面标题。
- 右上角历史记录图标，点击进入历史记录页。
- 设置入口放在同一顶部栏的菜单中，不能占用“右上角历史”这一固定交互。

设备卡：

- 左：心率/连接状态图标。
- 中：已连接心率带名称；未连接时显示“未连接心率带”。点击整卡打开设备扫描选择。
- 右：当前实时心率三槽数字 + `bpm`。连接后每秒更新一次。

主操作：

- “骑行记录”：V0.0.1 保留禁用/即将推出。
- “持续记录”：已连接后可进入记录页；未连接时先要求选择心率带。

## 5. 首次启动与设置

### 5.1 首次启动保活弹窗

首次启动仅自动展示一次，内容必须说明：

- 建议在最近任务/系统管家中对本应用加锁；此动作无统一 Android API，应用无法自动完成。
- 建议关闭电池优化/允许后台运行。
- 记录时若需要悬浮窗，需授予“显示在其他应用上层”权限。

提供“打开系统设置”和“稍后处理”。不能把厂商设置页打开成功等同于用户已经完成加锁。

### 5.2 设置页

至少包含：

- 悬浮窗权限：实时显示当前状态，点击跳转 `ACTION_MANAGE_OVERLAY_PERMISSION`。
- 后台无限制/电池优化：实时检测 `PowerManager.isIgnoringBatteryOptimizations()`，点击跳转系统对应页。
- 应用加锁/自启动指导：根据厂商尝试打开系统管理页；失败则回退到应用详情页。

## 6. BLE 心率连接

- 运行时权限：Android 12+ 请求 `BLUETOOTH_SCAN` 与 `BLUETOOTH_CONNECT`；Android 11 及以下按系统要求请求定位权限。
- 扫描优先发现广播标准 Heart Rate Service 的设备。
- 连接后发现 0x180D / 0x2A37，并启用通知。
- 解析 8-bit 与 16-bit Heart Rate Measurement 格式。
- GATT 回调只更新“最新收到的 BPM”；UI 与持久化采用 1 Hz 节拍读取该值，因此满足“每秒更新一次”，同时避免设备高频通知造成数据库爆量。
- 无有效测量时不伪造 0 bpm 样本。

## 7. 持续记录页

顶部显示设备名。

当前心率：大型三槽数字，`bpm` 独立显示。

曲线：

- 默认显示最新 1 小时；不足 1 小时显示现有记录区间并保留真实时间刻度。
- X 轴显示真实 `HH:mm`，24 小时制。
- 可左右拖动历史窗口；达到记录头/尾后允许约 8% 视窗宽度的阻尼超拖，松手使用 180–260ms 回弹动画。
- 数据每秒增加一点；当用户停留在最右端时视窗自动跟随最新数据；用户主动向左查看历史后不强制抢回右端。
- 折线下方填充绿色渐变，靠近线条较明显，向图表底部逐渐透明；不使用整块实色填充。
- 历史详情复用完全相同的曲线 View、坐标计算、拖动与回弹。

### 7.1 Y 轴心率档位规则

除特别说明外，心率坐标数字以 25 bpm 为一档，向上取整。

基础三值语义：最大档、平均档、0。

持续记录页和历史详情页属于“特别说明”的主曲线，额外在平均档与最大档之间显示一个中间档，因此主曲线实际显示 4 个水平标记：

1. 最大档 `maxBand`
2. 中间档 `midBand`
3. 平均档 `avgBand`
4. `0`

规则：

- `ceil25(v) = ceil(v / 25) * 25`
- `avgBand = max(25, ceil25(avgBpm))`
- `rawMaxBand = max(25, ceil25(maxBpm))`
- 为保证中间档仍是 25 的整数档且不与上下档重叠：`maxBand = max(rawMaxBand, avgBand + 50)`
- `midBand` 取 `[avgBand + 25, maxBand - 25]` 内最接近 `(avgBand + maxBand) / 2` 的 25 整数档。

这样所有显示档位始终是 25 的整数倍，且主曲线总能显示一个独立中间档。

## 8. 悬浮窗

仅在“正在持续记录 + 应用不在前台 + 已有悬浮窗权限”时显示。

- 大号当前 BPM：三槽数字 + `bpm`。
- 下方迷你 60 秒趋势图。
- 左侧三个小矩形心率值分别对应当前记录的 `最大档 / 平均档 / 0`，全部按 25 档规则显示；平均档处画虚线参考线，与草图语义一致。
- 长按/拖动可移动位置；松手保持在屏幕可见范围内。
- 单击（没有发生有效拖动）返回当前持续记录页面。
- 悬浮窗不抢占输入焦点。

## 9. 停止记录

底部使用“长按停止”。

- 按住满 900ms 才触发停止。
- 显示按压进度和轻触觉反馈。
- 停止后写入 `endTimeMs`、总时长、最大心率、平均心率；同一记录只允许完成一次。
- 停止后关闭该记录对应悬浮窗并回到主界面/历史可见状态。

## 10. 数据库

Room 两张表：

`recording_session`

- `id` PK
- `type` (`CONTINUOUS` / 预留 `RIDING`)
- `startTimeMs`
- `endTimeMs`
- `durationMs`
- `maxBpm`
- `avgBpm`

`heart_rate_sample`

- `id` PK
- `sessionId` FK
- `timestampMs`
- `bpm`
- 索引：`sessionId,timestampMs`

停止记录时聚合统计来自实际已写入样本；没有有效样本时最大/平均值显示为 `---`，不能伪造数据。

## 11. 历史记录

列表默认按 `startTimeMs DESC`。

每项显示：

- 记录类型（V0.0.1 只有“持续记录”）
- 日期：`yyyy-MM-dd HH:mm`
- 总时长
- 最大心率
- 平均心率

点击项后：

- 原卡片视觉放大为居中详情层，带 scale/fade 动画。
- Android 12+ 对底层列表使用 `RenderEffect` 高斯模糊；旧系统使用 dim/fade 降级。
- 顶部显示同样 5 个摘要字段。
- 下方使用与持续记录页同一个 `HeartRateChartView`，默认最新 1 小时，可左右拖动和回弹。

## 12. 质量与测试门槛

V0.0.1 合并/发布前至少满足：

- `./gradlew testDebugUnitTest`
- `./gradlew lintDebug`
- `./gradlew assembleArm32Release assembleArm64Release`
- `HeartRateMeasurementParser`：8-bit/16-bit/非法数据单测。
- 25 档坐标规则单测，覆盖边界值 0/1/24/25/26/100/101/125/126 及平均档接近最大档场景。
- 记录统计单测（空样本、单样本、多样本）。
- CI 全绿后才允许发布 V0.0.1。

## 13. 32/64 位发布

应用主体是 Java/Dex，不依赖原生 `.so`，因此从执行能力上一个 APK 本来就能同时运行于 32/64 位 ARM Android。为满足分开发包需求，构建定义两个发布 flavor：

- `arm32`：标识/过滤 `armeabi-v7a`
- `arm64`：标识/过滤 `arm64-v8a`

输出分别命名为：

- `Heart-Rate-Strap-Companion-v0.0.1-arm32.apk`
- `Heart-Rate-Strap-Companion-v0.0.1-arm64.apk`

两者 Java 业务逻辑完全一致。V0.0.1 CI 可使用开发签名产出可安装测试包；正式长期发布前必须改为仓库 Secrets 注入的固定 release keystore，禁止把生产私钥提交到公开仓库。

## 14. 发布门槛

版本号从 `V0.0.1` 开始（Git tag/Release 使用 `v0.0.1`）。发布流程必须在测试与 lint 成功后执行。Release 页面同时上传 32 位与 64 位 APK，并附带：

- 仅实现持续记录；骑行记录未开发。
- 标准 BLE Heart Rate Service 兼容说明。
- 后台保活与悬浮窗权限说明。
- 开发签名/正式签名状态。
